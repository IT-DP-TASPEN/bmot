`saldoNeraca2` reverses COAs beginning 2, 3, 4, or 6 (and separately reverses `1272005`, which these metrics do not use). SALAK annualizes BOPO's numerator and denominator equally, leaving its ratio unchanged. NIM annualizes interest income and expense and averages monthly productive assets. LDR excludes `2212111`, `2212116`, and `2212199` from its deposit base. Cash Ratio subtracts `branch_saldo_aba_blokir` from liquid assets. **This application has no authoritative blocked ABA source.** Its historical implementation uses the dashboard owner's earlier zero assumption, so it can differ from SALAK when blocked ABA is nonzero. No substitute has been inferred.

The current `DashboardService` has mock and DWH implementations. Handlers own one global `daily`/`monthly`/`yearly`, period, and branch filter; HTMX swaps only `#main`, and `app.js` redraws charts after swaps and updates sidebar links. The DWH service reads position snapshots for selected dates, computes Booking flows from `periode_mulai`, and sends page DTOs to templates. The chart DTO has ordered labeled points but no source metadata. The only configured database is a dedicated read-only DWH MySQL pool; there is no application snapshot database or Fincloud configuration in this repository.

The supplied Savings and Time Deposit CSV samples confirm the headers and amount/date formats above. The user confirmed those reports do not paginate or omit branches. This repository has no Fincloud credentials, so live endpoint authentication and reconciliation to the DWH remain manual deployment checks. Balance Sheet branch attribution follows dwh-v2: use the requested branch because the CSV's `Branch` field can differ. A missing or invalid report cannot publish a new generation. The DWH source must never be used as an unlabeled substitute for today's missing realtime snapshot.
